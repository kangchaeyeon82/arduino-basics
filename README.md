## 1. GPIO가 뭐예요?

> 📝 **메모:** GPIO는 프로그래밍이 가능한 핀이다.

**GPIO** = **G**eneral **P**urpose **I**nput **O**utput (범용 입출력)

아두이노 가장자리에 있는 작은 구멍(핀)들 중에서 **내가 코드로 "무슨 일을 할지" 정할 수 있는 핀**이에요.

| 이렇게 쓰면 | 하는 일 | 비유 |
|---|---|---|
| `pinMode(핀, OUTPUT)` | 전기를 **내보내요** (출력) | 🔦 손전등 스위치를 켜고 끄기 |
| `pinMode(핀, INPUT)` | 전기가 들어왔는지 **읽어요** (입력) | 👂 귀 기울여 듣기 |

> 💡 같은 핀이라도 코드에 따라 "말하는 핀"이 될 수도, "듣는 핀"이 될 수도 있어요!

## 2. 디지털 출력 — 5V / GND

> 📝 **메모:** 디지털 출력 5V, GND

디지털 출력은 **딱 두 가지**만 할 수 있어요. 켜거나, 끄거나!

| 코드 | 핀의 전압 | 결과 |
|---|---|---|
| `digitalWrite(핀, HIGH)` | **5V** ⚡ | LED 켜짐 💡 |
| `digitalWrite(핀, LOW)` | **0V** (= GND) | LED 꺼짐 ⚫ |

```cpp
digitalWrite(13, HIGH);  // 13번 핀에 5V → LED 켜기
delay(1000);             // 1초 기다리기
digitalWrite(13, LOW);   // 13번 핀을 0V로 → LED 끄기
```

> 💡 **GND(그라운드)** 는 전기의 "바닥"이에요. 0V 기준점이라서, 전기는 항상 5V에서 출발해 GND로 돌아와야 길(회로)이 완성돼요.

> 🧪 **해 본 것:** A0 같은 아날로그 핀도 `digitalWrite`로 디지털 출력을 할 수 있어요! → [Blink_A0](Blink_A0/Blink_A0.ino)

## 3. 디지털 입력 — 1이야? 0이야?

> 📝 **메모:** 같은 노드의 전압을 읽는다. 5V에 가까운지 0V에 가까운지 판단해서 1, 0

**노드**는 전선으로 이어져서 **전압이 같은 한 덩어리**를 말해요.
아두이노는 핀과 같은 노드에 있는 전압을 재고, 이렇게 판단해요.

```
 5V ┤ ███████████  → 1 (HIGH) "5V에 가깝네!"
    │ ███████████     약 3V 이상
 3V ┤ - - - - - - -
    │ ░░░░░░░░░░░  → ❓ 애매한 구간 (어떻게 읽힐지 몰라요)
1.5V┤ - - - - - - -
    │ ███████████  → 0 (LOW)  "0V에 가깝네!"
 0V ┤ ███████████     약 1.5V 이하
```

```cpp
int state = digitalRead(2);  // 2번 핀이 5V 쪽이면 1, 0V 쪽이면 0
```

## 4. 버튼의 여러 문제점 🔘

> 📝 **메모:** 버튼의 여러 문제점 — 풀업·풀다운 / 디바운싱 / 상태변화 / 인터럽트

버튼은 그냥 꽂으면 될 것 같지만, 사실 **4가지 함정**이 숨어 있어요!

### ① 풀업 · 풀다운 — "아무 데도 연결 안 된 핀"의 문제

버튼을 **안 누르고 있을 때**, 핀이 5V에도 GND에도 연결되어 있지 않으면 어떻게 될까요?
→ 핀이 **둥둥 떠 있는(floating) 상태**가 돼서 1과 0을 제멋대로 왔다 갔다 해요. 😵

그래서 저항으로 핀을 한쪽에 **살짝 붙잡아** 둬요.

| 방식 | 연결 | 안 누를 때 | 누를 때 |
|---|---|---|---|
| **풀업** (Pull-up) ⬆️ | 저항으로 핀을 **5V**에 연결 | 1 (HIGH) | 0 (LOW) |
| **풀다운** (Pull-down) ⬇️ | 저항으로 핀을 **GND**에 연결 | 0 (LOW) | 1 (HIGH) |
| **내부 풀업** ✨ | 아두이노 **안에 있는** 저항 사용 | 1 (HIGH) | 0 (LOW) |

```cpp
pinMode(2, INPUT_PULLUP);  // 내부 풀업! 저항 없이 버튼만 2번 핀 ↔ GND에 꽂으면 끝
```

> 💡 **내부 풀업이 제일 편해요.** 저항을 따로 안 꽂아도 되거든요. 대신 **누르면 0, 안 누르면 1**로 거꾸로 읽힌다는 것만 기억하세요!

### ② 디바운싱 — 버튼이 "덜덜덜" 떨리는 문제

버튼 속 금속 조각은 누르는 순간 **공이 바닥에 통통 튀듯이** 몇 ms 동안 붙었다 떨어졌다 해요.

```
내가 생각한 것:   ‾‾‾‾‾‾‾|_______________   (딱 한 번 눌림)
실제 신호:        ‾‾‾‾‾‾‾|_|‾|_|‾|________   (여러 번 눌린 것처럼 보임 😱)
                         └ 떨림(바운싱) ┘
```

아두이노는 아주 빨라서 이 떨림을 **여러 번 누른 것**으로 착각해요.
그래서 **"값이 잠깐(약 50ms) 그대로 유지될 때만 진짜로 인정"** 하는 것을 **디바운싱**이라고 해요.

```cpp
if (reading != lastReading) {          // 값이 바뀌었으면
  lastDebounceTime = millis();         // 바뀐 시각을 기록하고
}
if (millis() - lastDebounceTime > 50) {  // 50ms 동안 그대로면
  // 이제 진짜 상태로 인정!
}
```

> 🧪 **해 본 것:** 디바운싱을 빼 보니 한 번 눌러도 LED가 여러 번 바뀌었어요. 반대로 200ms처럼 너무 길게 하면 버튼을 **꾹** 눌러야만 반응했어요. **20~50ms 정도가 딱 좋아요!**

### ③ 상태 변화 감지 — "누르고 있는 것" vs "누른 순간"

`loop()`는 1초에 수천 번 돌아요. 버튼을 누르고 있는 동안 "눌렸다!"를 계속 세면 숫자가 순식간에 1000이 돼요. 😅

그래서 **현재값과 과거값을 비교**해서, **바뀌는 순간 한 번만** 세요.

| 과거값 | 현재값 | 의미 |
|---|---|---|
| 1 (HIGH) | 0 (LOW) | 🔽 **지금 막 눌렀다!** (이때만 세기) |
| 0 (LOW) | 0 (LOW) | 계속 누르고 있음 (무시) |
| 0 (LOW) | 1 (HIGH) | 🔼 지금 막 뗐다! |
| 1 (HIGH) | 1 (HIGH) | 안 누르고 있음 (무시) |

```cpp
if (lastReading == HIGH && reading == LOW) {  // 1 → 0 바뀐 순간!
  pressCount++;
}
lastReading = reading;  // 현재값을 과거값으로 저장
```

### ④ 인터럽트 — "하던 일 멈추고 바로 반응하기"

`delay(5000)`으로 5초 기다리는 동안 버튼을 누르면? → 아두이노는 **5초가 끝날 때까지 몰라요.** 🙉

**인터럽트**는 **초인종** 같은 거예요.
문 앞을 계속 쳐다보지 않아도, 초인종이 울리면 하던 일을 멈추고 바로 달려가죠! 🔔

```cpp
attachInterrupt(digitalPinToInterrupt(2), buttonISR, FALLING);
//                               ↑ 핀      ↑ 실행할 함수  ↑ 언제? (누르는 순간)
```

| 꼭 알아둘 것 | 이유 |
|---|---|
| 우노는 **2번, 3번 핀**만 인터럽트 가능 | 다른 핀은 `attachInterrupt`가 안 돼요 |
| 인터럽트에서 바꾸는 변수엔 **`volatile`** | `loop()`가 바뀐 값을 제대로 읽게 해 줘요 |
| 인터럽트 함수 안에서 **`Serial`, `delay` 쓰지 않기** | 짧고 빠르게 끝내야 해요 |

| 언제 실행할까? | 뜻 |
|---|---|
| `FALLING` | HIGH → LOW (누르는 순간, 내부 풀업일 때) |
| `RISING` | LOW → HIGH (떼는 순간, 내부 풀업일 때) |
| `CHANGE` | 바뀔 때마다 (누를 때도, 뗄 때도) |

## 5. 아날로그 출력 — PWM

> 📝 **메모:** PWM으로 펄스폭 변조를 해 아날로그 값을 표현한다

아두이노는 사실 **5V 아니면 0V**만 낼 수 있어요. 그런데 어떻게 LED를 **반만 밝게** 할까요?

👉 **엄청 빠르게 켰다 껐다** 하는 거예요! 눈이 따라가지 못해서 **중간 밝기**로 보여요.
이걸 **PWM** (Pulse Width Modulation, 펄스폭 변조)이라고 해요.

```
analogWrite(11, 0)    ________________________   0%   → 꺼짐 ⚫
analogWrite(11, 64)   ‾|___‾|___‾|___‾|___‾|___  25%  → 어둡게 🌑
analogWrite(11, 127)  ‾‾|__‾‾|__‾‾|__‾‾|__‾‾|__  50%  → 반 밝기 🌓
analogWrite(11, 191)  ‾‾‾|_‾‾‾|_‾‾‾|_‾‾‾|_‾‾‾|_  75%  → 밝게 🌔
analogWrite(11, 255)  ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾  100% → 최대 밝기 🌕
```

- 값은 **0 ~ 255**까지 넣을 수 있어요.
- 우노에서 PWM이 되는 핀은 숫자 옆에 **`~` 표시**가 있는 **3, 5, 6, 9, 10, 11번**이에요.

> 🧪 **해 본 것:** [Blink_Fast](Blink_Fast/Blink_Fast.ino)에서 깜빡이는 간격을 0.1초 → 0.05초 → 0.01초 → 0.005초로 줄여 봤어요.
> 점점 깜빡임이 안 보이더니, 결국 **반쯤 밝게 켜져 있는 것처럼** 보였어요. 이게 바로 PWM의 원리예요! 🎉
> (`analogWrite`는 이것보다 훨씬 빠른, 1초에 약 490번 켰다 껐다 해요.)

## 6. 아날로그 입력 — A0 ~ A5

> 📝 **메모:** 아날로그 입력 A0~A5, 같은 노드의 전압을 읽는다

디지털 입력은 1 아니면 0이었죠? 아날로그 입력은 **0V ~ 5V 사이를 1024단계**로 잘게 나눠서 읽어요. 📏

| 전압 | `analogRead()` 값 |
|---|---|
| 0V | 0 |
| 2.5V | 약 512 |
| 5V | 1023 |

```cpp
int value = analogRead(A0);            // 0 ~ 1023
float voltage = value * 5.0 / 1023.0;  // 전압(V)으로 바꾸기
```

> 💡 **값 범위 바꾸기:** 가변저항 값(0~1023)으로 LED 밝기(0~255)를 조절하려면 `map()`을 써요.
> ```cpp
> int brightness = map(value, 0, 1023, 0, 255);
> ```

## 7. 시리얼 통신

아두이노가 **컴퓨터에게 말을 거는 방법**이에요. 💬
코드가 잘 돌아가는지, 센서 값이 얼마인지 눈으로 확인할 수 있어요.

```cpp
void setup() {
  Serial.begin(9600);          // 통신 시작! 속도는 9600
}

void loop() {
  Serial.print("value: ");     // 줄 안 바꾸고 출력
  Serial.println(123);         // 출력하고 줄 바꾸기
}
```

**보는 법:** 아두이노 IDE 오른쪽 위 🔍 돋보기(시리얼 모니터) 클릭 → 오른쪽 아래 속도를 **9600 baud**로 맞추기

> ⚠️ 코드의 속도(`9600`)와 시리얼 모니터의 속도가 다르면 글자가 `⸮⸮⸮`처럼 깨져요!

## 8. 회로 결선

### 🧷 기본 규칙

- 모든 부품의 **GND는 아두이노 GND와 이어져야** 해요. (전기가 돌아올 길!)
- 브레드보드는 **같은 세로줄 5칸끼리** 연결되어 있어요. 저항 다리와 LED 다리가 같은 줄에 있어야 이어져요.
- 긴 브레드보드는 옆의 **+/− 줄이 가운데에서 끊겨** 있을 때가 있어요.

> 🧪 **겪은 일:** 신호등에서 초록은 켜지는데 노랑·빨강이 안 켜졌어요.
> 이럴 땐 코드보다 **LED 방향, 꽂은 핀 번호, GND 연결**을 먼저 확인해요!

### 🎛️ 가변저항

손잡이를 돌리면 저항값이 바뀌는 부품이에요. 다리가 **3개** 있어요.

```
   ┌───────────┐
   │  (손잡이)  │
   └─┬───┬───┬─┘
     │   │   │
    5V  A0  GND
   바깥 가운데 바깥
```

- **바깥 다리 2개** → 5V와 GND (방향은 바꿔도 괜찮아요, 돌리는 방향만 반대가 돼요)
- **가운데 다리** → 아날로그 핀(A0 등)
- 손잡이를 돌리면 가운데 다리의 전압이 0V ~ 5V로 바뀌어요.

### 💡 LED

```
 핀 ── [저항 220Ω] ── 긴 다리(+)  LED  짧은 다리(−) ── GND
```

| 확인할 것 | 이유 |
|---|---|
| **긴 다리 = +** (핀 쪽), **짧은 다리 = −** (GND 쪽) | 거꾸로 꽂으면 안 켜져요 |
| **저항 꼭 달기** (220Ω ~ 330Ω) | 저항 없으면 전류가 너무 많이 흘러 LED나 핀이 망가져요 🔥 |

### 🔘 버튼 (풀업, 풀다운, 내부 풀업)

4발 택트 버튼은 **마주 보는 다리끼리 원래 붙어 있어요.** 헷갈리면 **대각선** 위치의 다리 두 개를 쓰면 안전해요.

```
  풀업                  풀다운                내부 풀업 ✨
  5V                    5V                    (아두이노 안에 저항)
   │                     │
 [10kΩ]                [버튼]                 핀 ── [버튼] ── GND
   │                     │
  핀 ●                  핀 ●                  pinMode(핀, INPUT_PULLUP);
   │                     │
 [버튼]                [10kΩ]                 안 누름 = 1
   │                     │                    누름   = 0
  GND                   GND

 안 누름 = 1            안 누름 = 0
 누름   = 0            누름   = 1
```

## 9. 네오픽셀

**선 하나로 LED 여러 개의 색깔을 따로따로** 바꿀 수 있는 신기한 LED예요! 🌈
LED마다 작은 칩이 들어 있어서, 신호를 다음 LED로 차례차례 전달해요.

```
 아두이노 10번 ──▶ [LED0]──▶[LED1]──▶[LED2]── ... ──▶[LED7]
                    🔴       🟢       🔵              🟡
```

| 핀 | 연결 |
|---|---|
| **DIN** (신호 입력) | 아두이노 디지털 핀 (예: 10번) |
| **5V** | 5V |
| **GND** | GND |

```cpp
#include <Adafruit_NeoPixel.h>
Adafruit_NeoPixel strip(8, 10, NEO_GRB + NEO_KHZ800);  // 8개, 10번 핀

strip.begin();
strip.setBrightness(50);                          // 밝기 (0~255)
strip.setPixelColor(0, strip.Color(255, 0, 0));   // 0번 LED를 빨강으로
strip.show();                                     // ⭐ show()를 해야 실제로 바뀌어요!
```

> ⚠️ 라이브러리 매니저에서 **"Adafruit NeoPixel"** 을 먼저 설치해야 해요.
> ⚠️ 너무 밝게 켜면 전기를 많이 먹어요. 밝기는 50 정도로 낮춰서 쓰는 게 좋아요.

## ⬆️ 보드에 업로드하는 방법

### 방법 1. 아두이노 IDE

1. `.ino` 파일 열기
2. 위쪽에서 보드 **Arduino Uno**, 포트 **COM3** 선택
3. **→ (업로드)** 버튼 클릭 (또는 `Ctrl + U`)

### 방법 2. arduino-cli

```bash
arduino-cli compile --upload -b arduino:avr:uno -p COM3 "스케치 폴더 경로"
```

> ⚠️ 시리얼 모니터가 열려 있으면 포트가 막혀서 업로드가 실패할 수 있어요. 닫고 다시 해 보세요!
